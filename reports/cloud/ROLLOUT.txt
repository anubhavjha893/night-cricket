OPERATING LIMITS
Registration intentionally opens 24 November and closes after 20 December 2026
in India time. The live registration page clearly explains the opening date.
Submission and approval/notification behavior were verified with synthetic data
locally; live player submission remains unverified while the window is closed.
Do not open registration early solely to perform a production test.
Render free instances sleep after 15 idle minutes and can take about one minute
to wake. The frontend's bounded API timeout can expire during that cold start;
retry after the service wakes. Free instance hours are shared across the Render
workspace. This deployment does not establish production uptime or peak-load
assurance. Use an owner-approved paid always-on plan before requiring that.
Client forwarding headers are not trusted without verified proxy IP ranges;
TRUST_PROXY=0 prevents spoofing but multiple visitors may share the ingress IP
and its limits. Exact trusted ingress ranges/identity require host verification.
Password scheme remains in compatible phase 1; enable phase 2 consistently only
after all previous backend instances are drained, per the security rollout guide.
Atlas and Render credentials supplied in chat should be rotated by the owner;
update the corresponding provider secrets and redeploy after rotation.

DEPLOYMENT AND ROLLBACK
Vercel is linked to GitHub main; pushes can deploy automatically. Render auto
deploy is off, so backend changes require a deliberate deploy after tests.
Future releases should stage Vercel production builds with --prod --skip-domain,
test them, then promote. Gate release on readiness 200, 100% dedicated smoke-flow
success and no new 5xx. Monitor meaningful host-specific p95 and error-rate
windows before making production performance claims; no live traffic baseline
existed for the previously absent backend.
Use the Render dashboard's rollback action to a known healthy deploy. This is
the first backend release, so it has no earlier healthy backend rollback target;
retain this deployment as the first fallback. Do not roll back to a static-only
frontend when availability of registration is required. Vercel can roll back to
dpl_9SggDHwTDBrpfFRYtrrc4qE33qTy once a later release exists. Keep Render URL and
APP_ORIGIN unchanged, preserve additive indexes/collections, and do not restore
an old database snapshot over new registrations. Repeat readiness, admin login,
settings/list reads and revoked-session checks after a rollback.

.env.deploy containing authorised organiser credentials; never run as load).
